# Suggestions for future improvements

[← Back to the index](README.md)

None of these are specified in the PDF. They are recorded only as ideas for later discussion and must not be implemented in this exercise.

| Idea | What it would do | Why it's not in scope |
|---|---|---|
| Buy extra review credits | Let the firm raise the monthly limit once the plan is used up. | Not specified; billing is explicitly excluded by the brief. |
| "Remind me at reset" | Notify a lawyer when the plan resets, without spending anything automatically. | Not specified. |
| Warning when re-reviewing an already reviewed document | Point out in the confirmation that the AI will review the same text again. | Not specified. |
| Warning when reviewing a superseded version | Point out the newer version, with a link to it. | Not specified. |
| Grouping document versions | Show the earlier lease version nested under the newer one. | Not specified. |
| Severity summary and filters on the final result | Totals per severity and filter chips (useful for the 16-finding franchise agreement). | Not specified. |
| Review History section | A dedicated, less prominent screen listing every review of a document, with clear status badges (Completed, Failed, In progress). It would give access to failed reviews without cluttering the main screen, which stays focused on completed reviews. | Not specified. The answer if the customer ever asks for the full history. |
| Plan usage by lawyer | Show who spent which review this month. | Not specified. |
| Cancel a running review | Stop a review and release its slot. | Not specified. |
| Server-Sent Events | Push updates instead of polling. | Polling is enough for 3 users. |
| Finding-level diff between versions | Compare the findings for lease v1 and v2. | Not specified. |
